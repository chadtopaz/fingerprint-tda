# Fingerprint verification from ridge-pattern topology — replication code (release 1.1.0)

Replication code for

> Topaz, C. M., Arcila-Maya, N., Munch, E., Stanley, Z., and Ziegelmeier, L. *Topological summaries of fingerprint ridge patterns carry identity information.* Manuscript under revision, *Pattern Recognition*, 2026.

**Repository:** <https://github.com/chadtopaz/fingerprint-tda> · **Archive:** Zenodo, concept DOI [10.5281/zenodo.20772749](https://doi.org/10.5281/zenodo.20772749) (resolves to the latest version; each release also has its own version DOI).

The repository contains the complete analysis code and, under `Results/`, the aggregate numbers every table of the article is formatted from. It contains **no fingerprint images and nothing derived from them at the pixel or pair level**: the benchmarks are third-party data (see [Data](#data)), and feature banks, caches, pair scores and minutiae templates are regenerated by running the code.

## What the code does

Starting from raw FVC images, `Code/preprocess.py` produces enhanced binary ridge/valley maps. The pipeline (`Code/fingerprintTDA.R`) computes the ridge and valley Euclidean distance transforms of each map, downsamples them to 150 × 150, clamps and rounds them, and computes sublevel-set persistent homology (H₁, lower-star filtration on the triangulated grid, GUDHI through the R package TDA) globally and on 64 local patches. The resulting diagrams become Betti curves and persistence images. Eight verification methods score image pairs: three geometry baselines on the distance fields (unclamped, clamped and rounded as for persistence, and rigidly aligned), two untrained global topological summaries (Betti L¹, PI L²), a logistic model on pairwise topological features (TopoLR), a local optimal-transport matcher (LPOT) and their equal-weight fusion, with ablations and a tuned fusion as variants. Evaluation is identity-disjoint 5-fold cross-validation on FVC2000 DB1 (optical) and FVC2002 DB3 (capacitive) with finger-level bootstrap intervals, a public-domain minutiae matcher (NIST NBIS) under the identical protocol, a transfer of the DB1-fitted models to DB3, a fixed-model sensitivity experiment (six enhancement-parameter variants, four calibrated acquisition degradations of the probe) and a comparison with the cubical construction. The paper and its supplement specify every step; the code is the reference.

## Two ways to use this repository

**1. Reproduce every table from the released numbers (seconds, no data needed).**

```bash
python3 Code/make_tables.py --source-root Results --out tables      # 27 LaTeX fragments, byte-identical to the article's (any Python 3)
python3 Code/build_results_bundle.py check --final                    # the bundle's inventory, hashes, content policy and release scope
pdflatex Figures/fig_sublevel_filtration.tex                         # the filtration schematic of Figure 2
```

`Results/` mirrors the project layout (`Results/Outputs_regen_v2/analysis/ci_metrics.csv`, …) and holds, for every reported run, the bootstrap intervals and paired differences, the per-fold metrics and acceptance counts, the sensitivity summaries, the cubical and transfer comparisons, the calibration record of the degradation experiment and the preprocessing manifests (library versions, per-image hashes). `Results/INVENTORY.json` lists each file with its sha256 and source run.

**2. Reproduce the results from the data (days of computation).** Obtain the two benchmarks and prepare them as described in `Data/README.md`; then, from the repository root, in the order below. ## Software

**R** (≥ 4.3; reported runs: 4.5.3): `source("DEPENDENCIES.R")` installs tidyverse, readr, jsonlite, png, TDA, TDAvec, digest, future, future.apply, matrixStats, pROC, progressr, EBImage (Bioconductor) and reticulate. Persistent homology of the reported construction uses the GUDHI library bundled in TDA.

**Python** (3.10–3.14). The preprocessing environment is pinned (`Code/requirements-preprocess.txt`, or `-py314.txt` for Python 3.14; both verified bit-identical) and is the one to create first:

```bash
python3 -m venv .venv-preprocess && .venv-preprocess/bin/pip install -r Code/requirements-preprocess.txt
.venv-preprocess/bin/pip install -r Code/requirements-sensitivity.txt   # Pillow, scikit-image: degradations, calibration, NBIS wrapper
.venv-preprocess/bin/pip install -r Code/requirements-figures.txt       # matplotlib: the block diagram
.venv-preprocess/bin/pip install -r Code/requirements-cubical.txt       # Python GUDHI: the cubical construction only
```

**Cubical construction** (`Code_cubical/`): R reaches Python GUDHI through reticulate; tell R which interpreter to use with `options(fp.python = ".venv-preprocess/bin/python")` or the environment variable `FP_PYTHON` (an already set `RETICULATE_PYTHON` is also honoured). The triangulated construction of the paper needs no Python.

**NBIS 5.0.0** (reference matcher): `Code/reference_matcher/build_nbis.sh` is a Linux/GNU build recipe for NIST's source (two edits to a generated makefile for a current compiler and non-x86 CPUs; the script records the source hash). The wrapper runs any built `mindtct`, `bozorth3`, `nfiq` and `cjpegl`.

**Randomness.** All seeds are fixed in the code (fold assignment 20260110; TopoLR standardization sample 123; anchors by an image-specific seed under L'Ecuyer-CMRG; bootstrap 20261010; probe-role assignment 20261014 + fold). Feature extraction runs in `future.apply` workers with `future.seed = TRUE`, and the anchor draw pins the RNG kind, so results do not depend on the worker count or on the session's RNG settings.

## Data

FVC2000 DB1 (DB1_A, 100 fingers × 8 impressions, optical, 300 × 300 at 500 dpi) and FVC2002 DB3 (DB3_A, 100 × 8, capacitive, 300 × 300) are third-party benchmarks that we do not redistribute. `Data/README.md` says where to obtain them, how to lay them out, how `Code/preprocess.py` turns them into the binary maps the pipeline reads, and how to check a reproduced preprocessing against the released manifests. Nothing under `Data/` other than that README is tracked.
